01 / Motivation

Sandboxes limit where code runs.
They don't record what a call changed.

Tracking and undoing a call is a separate job.

Infrastructure sandbox

Where can code run?

bubblewrap, gVisor, Firecracker microVMs.

  • OS policy (Claude Code)
  • User-space kernel (GKE Agent Sandbox)
  • MicroVM (E2B, Vercel Sandbox)
RustScript Agent

What did this call change?

Each call gets an ID, a receipt and a version.

  • Run and attempt IDs
  • Compare-and-swap on the workspace head
  • Tool graph pinned per run

03 / Effect Sandbox

Follow one file write
from tool call to receipt.

Tool callwrite_file("race.txt", "first")
  1. 01
    Write to a private view

    Readers still see H0 while the tool writes.

    candidate: race.txt = first
  2. 02
    Prepare

    Stop the writer; save tree H1 and the result.

    prepare(H1, result)
  3. 03
    Commit

    One transaction: receipt, head, result, event.

    expected H0 → Head H1
  4. 04
    Read back

    Read the receipt back before replying.

    receipt fx_7a29
  5. 05
    Conflict or restore

    Losers stay readable; restore starts a new run.

    conflict / new run

Lost the reply? Look it up by attempt ID.

  • 01
    Journal

    Links run, call, attempt and events.

  • 02
    Receipt

    Records the candidate, head and tool result.

  • 03
    CAS conflict

    Two runs, one head: one commits, one conflicts.
